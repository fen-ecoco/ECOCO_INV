# ECOCO 出貨 × 包材 × 庫存 即時儀表板

宜可可循環經濟（ECOCO）內部使用的商品出貨、贈品、包材與庫存管理工具。單一 HTML 檔案（`index.html`）為主體，搭配可選的獨立後端（`server/`），免安裝複雜環境即可使用。

---

## 功能總覽

### 📊 儀表板
- 依「今日／本週／本月／全部區間／自訂區間」篩選資料，全部以**台灣時間 GMT+8** 計算
- 下拉選單下方會即時顯示該區間對應的實際日期（淺灰色小字，切換選項immediately更新，不用按套用）：
  - 今日 → `2026-07-29`
  - 本週（週日～週六）→ `2026-07-26~08-01`
  - 本月 → `2026-07-01~07-31`
  - 全部區間 → `2020-01-01~2029-12-31`
- 商品出貨總覽：出貨量、贈品量、退貨筆數、目前總庫存、低庫存警示品項數
- 包材使用總覽：使用量／成本、入庫量／成本、目前總剩餘量、低庫存警示品項數
- 商品／包材即時庫存卡片：
  - **交叉篩選搜尋**：可用商品／包材名稱、目前庫存、安全庫存多條件組合搜尋（空格或頓號分隔多個關鍵字，需同時符合）
  - 獨立分頁導航（5 / 10 / 50 / 100 / 500 / 1000 筆／頁）
- 出貨與包材紀錄依篩選區間即時顯示，商品／包材皆會標示「名稱＋尺寸／規格」

### 📝 每日填寫
- **出貨**：選商品、數量、日期、備註
  - 可加入多筆**贈品品項**（贈品本身也是商品），出貨與贈品會合併存成**同一筆**紀錄，一起檢查並扣除庫存，任一項庫存不足會整筆擋下
  - 出貨送出後，系統依商品（與贈品）設定的預設包材，跳出視窗建議包材用量，勾選確認後**合併成一筆**包材使用紀錄（不會拆成多筆）
  - 商品／贈品下拉選單皆顯示「商品名稱＋尺寸」
- **包材**：入庫（增加庫存）／使用（扣除庫存），自動計算金額，下拉選單顯示「包材名稱＋規格」
- 出貨與包材紀錄皆可**編輯**（含贈品明細、合併包材明細）與**刪除**（僅管理者），庫存不足會跳出警示並阻擋，避免產生負庫存
- 出貨紀錄、包材紀錄皆支援 **CSV 匯出／匯入／範本下載**（CSV 匯入為批次作業，不會逐筆彈出確認視窗，完成後統一彙總彈出一次讓你確認是否建立包材紀錄）

### 📦 商品設定 / 🧾 包材設定
- 只需設定一次基本資料，之後每天只要在「每日填寫」填數量
- 商品：名稱、**尺寸**、目前庫存、安全庫存、備註、出貨預設包材（可設定多筆，每件用量為整數）
- 包材：名稱、**規格**、單價／費用、目前剩餘量、安全庫存、備註
- 「商品名稱」「尺寸」「包材名稱」「規格」四個欄位打字時會**自動帶出過去建置過的建議清單**（也可以直接輸入全新內容），建議清單會持續累積、不會因刪除商品/包材而消失；各卡片右上角有「🗑 清除建議清單」按鈕可手動清空（僅清空打字建議，不影響任何實際商品/包材資料）
- 「目前庫存／剩餘量」**低於安全庫存時數字會自動變成紅色粗體**，方便快速辨識需要補貨的品項
- 商品／包材皆可 CSV 匯出、匯入、下載匯入範本
- 每筆新增／編輯都會記錄操作時間與操作人

## ⚠️ 兩種運作模式

**模式 A：在 Claude.ai Artifact 中使用**
- 資料儲存透過 Claude.ai 平台提供的 `window.storage` API
- 免架設任何東西，開啟 Artifact 連結即可用
- 缺點：只有在 Claude.ai 對話介面中才能開啟，無法用一般網址分享

**模式 B：獨立部署（已測試可行，目前實際使用中）**
- `server/`（Node.js 後端）+ `storage-shim.js`（前端儲存轉接層）
- `storage-shim.js` 只在偵測不到 `window.storage`（不在 Claude.ai 環境）時才會啟動，改用 HTTP 呼叫 `server/` 提供的 API
- 資料庫為 `server/data/db.json`（JSON 檔案），任何人連到伺服器所在網址（區網 IP 或內部主機網址）就能共同讀寫同一份資料，無需 Claude.ai
- **目前狀態**：已在本機與同事的區網環境測試成功（含防火牆開通、`0.0.0.0` 監聽），可正常共同讀寫資料

### 模式 B 使用步驟

```powershell
cd D:\info\ECOCO_INV\server
npm install
npm start
```

啟動後顯示：
```
ECOCO_INV 後端伺服器已啟動：http://localhost:3001
```

- 自己電腦測試：瀏覽器開 `http://localhost:3001/`
- 同事在同一個公司網路測試：把 `localhost` 換成你電腦的區網 IP（`ipconfig` 查詢），例如 `http://192.168.0.64:3001/`
  - 若連線被拒絕，需要開通防火牆：以系統管理員權限執行
    ```powershell
    New-NetFirewallRule -DisplayName "ECOCO_INV Node Server" -Direction Inbound -Protocol TCP -LocalPort 3001 -Action Allow
    ```
- 全部測試沒問題後，把整個 `D:\info\ECOCO_INV` 資料夾（含 `server/`）搬到公司內部主機，執行同樣的 `npm install && npm start`（建議搭配 `pm2` 等工具讓服務常駐、開機自動啟動），之後大家改用內部主機的固定網址即可（此階段尚未執行）

### 檔案結構

```
D:\info\ECOCO_INV\
├── index.html          # 前端主程式
├── storage-shim.js      # 儲存轉接層（非 Claude.ai 環境才會啟動）
├── README.md
├── .gitignore
└── server/
    ├── server.js         # 後端 API（Express + JSON 檔案資料庫）
    ├── package.json
    └── data/db.json       # 實際資料（不進 git，執行後自動產生）
```

GitHub 這個 repo 用途：**程式碼版本控管與備份**；實際資料庫檔案 `server/data/db.json` 不會進 git，只存在跑伺服器的那台機器上。
